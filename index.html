What I build

Agent harnesses
A bounded tool-calling loop, routing between a fast deterministic path and the full agent, parallel tool calls, and a watchdog for stalled runs. In OVVE that loop drives 21 tools.
Evaluation you can trust
Persona-based scenarios graded by a semantic judge. The first full run of the OVVE suite found memory-recall and context-isolation defects that months of manual testing had missed.
Memory and retrieval
Structured records for exact state, an entity graph for relationships, semantic recall for the fuzzy rest, and each question answered by the store that can answer it.
Guardrails on real actions
A confidence gate on every autonomous write: high confidence acts, medium asks the user, low does nothing. An output verifier that replans when an answer fails a check.
Cost and observability
Token cost and latency traced per call in LangSmith, and an operating cost model at 10,000 users built before pricing was set.
Backend that holds up
Event-driven microservices, Kafka pipelines, zero-downtime migrations, CI that runs in minutes, and alerting on the failures that matter. Java, TypeScript and Python on AWS, Azure and Cloudflare.

What you can hand me

A problem with a vague edge and a real deadline. I take it from there:

  • Architecture and technology choices, written down with the reasons, so the next engineer is not guessing.
  • Delivery to production, including the release plan, the rollback, and the dashboards that show it worked.
  • Quality you can measure, through tests, contract checks and evals instead of manual confidence.
  • Security and data handling, from auth to third-party access, as part of the design rather than a review at the end.
  • The engineers around it. I have led a five-engineer team and mentored engineers on test-driven development and contract testing.
